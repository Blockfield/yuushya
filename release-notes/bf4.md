# Blockfield/yuushya bf4

## Кратко

Yuushya bf4: `YuushyaRegistries` регистрирует `ride_entity` вызовом `build()` без id вместо `build("ride_entity")` — пропадает строка `ERROR "No data fixer registered for ride_entity"` при загрузке сервера. Регистрация идентична (ванильный поиск DataFixer всё равно отбрасывал результат), меняется только побочный ERROR в логе. В промежутке с bf3 — только EOL/CI, на игру не влияет. Апстрим тот же (Yuushya 2.3.0).

## Для игроков

Изменений для игроков нет: модели, текстуры, коллизии дверей и поведение — как в bf3 (подтверждено распакованным сравнением кандидата с опубликованным bf3: из 54700 записей изменён только класс регистрации). В серверном логе стало чище (один ERROR меньше). Обновляться нужно только за новым пином (имя файла bf4).

## Технические изменения

- `scripts/PatchYuushya.java`: новый шаг `fixEntityDataFixers` (LDC-патч лямбды `registerAll`, ровно-1) для `YuushyaRegistries`; `scripts/patch.py`: новый `entity_class` (имя выхода не менялось).
- `tests/YuushyaPatchChecks.java`: проверки на реальном классе (1×`build(String)` до, 1×`build()` + 0×`build(String)` после, детерминизм, отказ идемпотентности и отказ на классе без LDC); `tests/test_patch.py` пропускает entity-класс через патч.
- Сборка пишет `files/mods/yuushya-1.21.0-fabric-2.3.0-bf4.jar` через кандидат + атомарную замену.
- `BUILD-SHA256SUMS` и `SHA256SUMS` записывают проверенный кандидат bf4 (по прецеденту bf3). Релизы import-2.53.0/bf3 не заменяются.

## Обновлённые компоненты

Upstream остаётся Yuushya 2.3.0 для Fabric 1.21.1. По сравнению с bf3 изменён один класс (`YuushyaRegistries`, вызов регистрации `ride_entity`) плюс EOL/CI правки рецепта; починки ресурсов, join-notice и door-shape патчи совпадают с bf3.

## Совместимость и необходимые действия

Мод имеет `side = "both"`: после публикации одинаковый новый URL и SHA должны быть закреплены в клиенте и сервере; выпуск парный, production Deploy — только с подтверждением владельца.

## Известные проблемы

Новых игровых проверок стенда для bf4 не выполнялось (патч регистрации проверен перезаписью байткода и сверкой кандидата). Наследованных игровых ограничений приёмки рецепта нет.

## Источники и ограничения полноты

- Коммиты bf3..bf4: #10 (раннеры), #11/#12 (Blacksmith), #13 (self-hosted остатки), EOL (#14/#15), 2da4d05 (ride_entity build без id, #16), плюс коммит подготовки релиза bf4.
- Проверено локальным `just check` + `just build` с верификацией checksum кандидата и повторной сборкой до тех же байтов. Игровых замеров стенда для bf4 нет.
